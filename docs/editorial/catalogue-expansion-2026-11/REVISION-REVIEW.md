## ILR review boundary

Article 13(4)(a) generally uses **more than two continuous years** outside the UK and Islands. Article 13(4)(za) uses **more than five**, or **more than four** if Appendix EU leave was granted as a Swiss national or a family member of a Swiss national. The Swiss category is about the basis of the grant. Articles 13A–13C describe specific overseas postings and accompanying-person exceptions. The draft confines its thresholds to the comparison of indefinite leave. It points readers with pre-settled status to Appendix EU for a separate qualifying-residence check and avoids a blanket claim about cancellation or other rights, such as rights under the Withdrawal Agreement.

The operative rules and caseworker guidance agree on the settled-status thresholds. The GOV.UK public overview summarizes pre-settled lapse with a general five-year figure. The text of the Order and Home Office operational guidance also distinguish the Swiss four-year category for Appendix EU limited leave. The draft avoids quoting a pre-settled threshold in the comparison table. Absence, cancellation, permanent residence under an agreement and qualification for a status grant can have different outcomes. Individual cases and any reform effective dates should be checked again before publication. ## Existing owner-controlled publication path

The path below uses the implemented multilingual editorial backend. It requires separate owner publication authorization and an authorized private operator. The existing GitHub manifest workflow checks that a slug is new and supplies an empty current-publication expectation. A passing ZIP check cannot authorize these replacements. No protected manual replacement dispatch or reusable replacement client was found in the current runbook or workflow files. Before a future release, the owner must confirm the approved host operator can use the existing private draft and approval sessions and production review service for this specific operation. Existing service credentials stay in their private custody. The DRAFT or APPROVAL browser session alone cannot record locale reviews.

1. Verify the lock and current open publication UUID, parent source revision, batch and five locale revision hashes. Retain the previous reviewed draft bodies and a verified off-instance backup. Check for competing drafts and preserve the existing validity policy. Compare all reviewed file and canonical hashes with the package manifest.
2. Through the loopback owner API, authenticate a DRAFT session and use `POST /api/owner/editorial/batches` with the reviewed zh-CN `source`, `basedOnRevisionId` set to the current source revision, a stable unique `idempotencyKey`, approved `policyVersion` and `sourceVersion`, and the intended `validFrom` and `validUntil`. Record the returned batch ID, revision ID and digest. Use the translation export and import endpoints for the other four reviewed drafts, keeping the batch ID, source revision and source hash bound to each file. Read back the batch and verify all five locale IDs and hashes. The public variants must still match the previous publication.
3. Use the existing authorized production review service for `POST /api/editorial/guide-batches/{batchId}/reviews/{locale}`. Each review pins `contentHash`, `passed` and `findings` to the actual reviewed artifact. Record the true review provenance. Then the authorized owner uses an APPROVAL session to explicitly approve the exact batch through `POST /api/owner/editorial/batches/{batchId}/approve`. Take and verify the pre-publication backup under the current runbook.
4. Record the new open publication ID, final hashes and the superseded IDs. Verify all five detail endpoints, category listings and sitemap/hreflang and compare unrelated Guides. Use the new open UUID as the expectation and repeat the five-locale review and approval. The store retains superseded bodies but refuses a second publication of an already-used revision. For emergency removal only, an authorized operator can use `--guide-withdraw=<slug> --expect-current=<publication-uuid> --reason=<reason>`, verify removal publicly and refresh static pages.
