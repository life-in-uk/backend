读者正文模板

H1 = 具体任务 + 英国或适用地域，例如「英国宽带怎么选：查地址、比较总价与办理换网」。
摘要 = 读者要决定什么、先做哪一步。显示最后核验日期、GB/UK/NI 或英格兰范围。
开头 = 三步以内的行动；写需要、可选、通常须遵守的合同条件各自适用谁。
1. 什么是这项保障/服务。放一张类别/适用情形/不包含什么的表；先写起保事件
   或实际交付内容，再写政策或商业条款中最易误解的词。
2. 报价或收费怎么拆。按同一份输入比较；列出一次性、分期、附加、期满、
   退出费用与最坏自付。没有已核验报价时，用空白字段、计算公式或条件提示。
3. 用合同核对关键细节。看范围、免赔额、单件/按病种/按年限额、起保时间和
   地域；服务合同查最低期、安装、设备归还与开放费用；对易混用的产品做短对照。
4. 开通、换保/换服务、续期、取消。给办理顺序、例外、证据、确认和结束日期；
   不把停止扣款写成退订，不保证豁免费用。查冷静期起点和例外。
5. 出问题怎么办。区分应急、故障、索赔、正式投诉；提供有管辖权的机构，不
   混用 Ofcom ADR、Energy Ombudsman、FOS 和 FSCS。不要承诺赔付结果。
6. 常见问答 3–5 个。优先回答实际陷阱，规则带适用范围。然后用能带去签约的
   清单收尾，附官方入口和最后核验日期。
术语做法 = 第一次写「中文（英文）」，避免用近义中文混淆。excess 是索赔
自付额，co-payment 多为比例自付，premium 是保费，sum assured 是约定保额。
standing charge 是按日固定费，direct debit 是付款安排。保留书面术语供比对。

后台交接与五语证据

现有 GuideImportReader 读 slug、category、title、summary、content、status、
publishedAt、updatedAt、sources、evidence。sources 记录 key、organisation、
title、url、accessedAt。evidence 每条有 key、statement 和 supports；
support 用 sourceKey、locator、excerpt、note。事实出处使用正文
[查看依据](#guide-evidence-<key>)，statement 与文中事实对应。短引文保留英文
原文；用中文 note 说明结论和限制，其他语言保留同一定位与同一事实范围。
正文日期与元数据应一致，证据检查日期不等于监管规则的生效日。

本包是 owner review 的文本。确认新 category、路由、导航和发布清单后再转换为
DRAFT、publishedAt=null 的源 JSON，并单独计算 guide-content-v1 哈希。Education
Hub 的源修订、翻译导出、独立审核、哈希绑定和人工审批模式可复用；当前
deploy/publish/promote.py 的批准清单只涵盖那一批学校指南，本栏目需独立批准
批次及哈希。目前拟议的一般类 checklist 是 standard-v1，以实际后端分类和编辑
合规复核为准。技术通过不等于内容或金融合规批准。

先审 zh-CN。锁定中文修订 ID 和 canonical digest 后，创建 zh-TW、en、ur、hi。
用共同术语表核对英式英语、繁体地区用词、乌尔都 RTL 及印地语金额与数字；
只在五语实际公开后生成对应链接与 hreflang。对换网、更换保险、索赔费用
和英国行业名词，不根据目标语言国家的惯例替换英国事实。
